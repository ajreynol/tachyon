# Experiment data retention

This directory tracks the eight derived gap lists used by the recorded
experiments and published report. Each row contains a benchmark identifier,
reference CPU seconds, and comparison CPU seconds or an unsolved status.
They are generated by `tools/heuresis/reports/gap --gapset`; the citing ledger entries
record the input runs and comparison settings. New `gapset-*.txt` lists are
ignored by default and require deliberate retention under the repository
[policy](../../../../docs/maintenance.md#result-retention).

The current-main combined control and eager-module-off control from
2026-09-16 were moved here from the obsolete `ledger/data/` directory on
2026-09-21, with their contents unchanged. Their provenance and report citations
are appended to the [current-main entry](../../docs/ledger/2026-09-16-rebased-equality-and-evaluator-branches.md#retention-update--2026-09-21)
and [eager-instantiation entry](../../docs/ledger/2026-09-16-bounded-eager-instantiation.md#retention-update--2026-09-21).

Raw `results-*.txt`, `stats-*.txt`, `stats-*-processed.txt` and `errors-*.txt`
are never tracked. Results and error sidecars live in `~/analysis/data/` on
the execution host; statistics and proof summaries live in `~/analysis/stats/`.
Use the host and job name in the launch log and ledger to retrieve them:

```bash
job_launcher/fetch -d scratch/results JOB_NAME
```

Recomputing a list requires those raw artifacts or access to the recorded
solver builds and benchmark corpus, not just this checkout. Historic commands
using `data/` as an input directory describe local files; substitute
`scratch/results/` when running them from the repository root.

If a generated list is needed as input to a follow-up experiment, recreate or
fetch it locally under its recorded name. Record aggregate conclusions and
the generation command in the ledger. Retain only data needed for a recorded
finding or report, with its schema and provenance. See the
[retention correction](../../docs/ledger/2026-09-19-output-retention.md) for the disposition
and checksums of the removed output files.
